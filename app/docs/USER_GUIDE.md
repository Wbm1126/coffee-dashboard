# 豆迹 v1.0 使用手册

本手册面向在个人电脑上长期使用豆迹的用户。豆迹是本地应用：页面运行在浏览器中，数据由同一台电脑上的本地服务保存。

## 1. 安装与首次启动

### 1.0 Windows 一键版（推荐）

从 GitHub Releases 下载名称形如 `CoffeeDashboard-v版本号-win-x64.exe` 的最新文件，双击后等待浏览器自动打开即可。无需另行安装 Node.js 或 Chromium。程序会驻留在 Windows 通知区域：双击图标可重新打开页面，右键可打开数据目录或退出豆迹。

一键版的个人数据固定保存在 `%LOCALAPPDATA%\CoffeeDashboard\data`，更新或重新下载可执行文件不会删除该目录。首次运行未经代码签名的个人项目时，Windows 可能显示 SmartScreen 提示；请先核对 Release 页面提供的 SHA-256，再选择运行。只从本项目 GitHub Release 下载，不要使用第三方转载文件。

### 1.1 环境要求

- Node.js `>=22.12 <27`，推荐当前受支持的 LTS 版本。
- npm（随 Node.js 安装）。
- Chromium 由首次设置命令安装，用于端到端验证和 PDF 导出。

### 1.2 安装

在 PowerShell 中进入仓库的 `app` 目录：

```powershell
npm ci
npm run setup
npm run doctor
```

`doctor` 会检查 Node.js、数据目录读写权限和 Chromium。全部显示 `✓` 后即可启动。

### 1.3 生产方式启动

```powershell
npm run build
npm start
```

看到“豆迹已启动”后，打开 `http://127.0.0.1:4173`。关闭运行该命令的终端，或按 `Ctrl+C`，即可停止服务。

### 1.4 开发方式启动

```powershell
npm run dev
```

打开 `http://127.0.0.1:5173`。开发模式会监听源码变化，仅建议开发和调试时使用。

## 2. 数据位置与自定义配置

默认目录结构：

```text
coffee-dashboard/
├─ app/
└─ data/
   ├─ coffee-data.json
   ├─ coffee-data.revision.json
   ├─ backups/
   └─ exports/
```

- `coffee-data.json`：主数据。
- `coffee-data.revision.json`：持久化版本高水位，用于防止旧页面覆盖新数据。
- `backups/`：自动、手工和恢复相关备份。
- `exports/`：已生成的 Markdown 与 PDF。

可在启动命令前设置环境变量：

```powershell
$env:COFFEE_DASHBOARD_PORT = '4173'
$env:COFFEE_DASHBOARD_CLIENT_PORT = '5173'
$env:COFFEE_DASHBOARD_DATA_DIR = 'E:\CoffeeDashboardData'
npm start
```

`COFFEE_DASHBOARD_CLIENT_PORT` 仅影响开发模式允许的前端来源。路径包含空格时仍需使用引号。不要让两个豆迹进程同时使用同一个数据目录。

## 3. 从历史 Excel 开始

首页的迁移入口需要同时选择：

1. 完整版工作簿：商品详情与扩展信息。
2. 选单工作簿：关注、饮用状态和历史评分。

豆迹先生成预览，不会直接改写原文件。请依次检查新增项、可能重复、字段冲突和无法识别项，再确认提交。重复导入同一批文件不会无限复制相同记录。

如果你没有历史工作簿，可以跳过迁移，直接从“补录喝过的豆”或联网采集开始。

## 4. 补录尚未登记的饮用与评价

这是 v1.0 的首要流程：

1. 打开“补录喝过的豆”。
2. 从已有豆档案中选择，或创建只有品牌和豆名的最小档案。
3. 填写实际饮用日期和冲煮方式。
4. 分别填写美式、奶咖评价；没有尝试的维度保持空白，不要用零分代替。
5. 填写综合等级、回购判断和总结，然后保存并继续下一条。

一次饮用只能关联一支豆。同一支豆可以保留多次饮用记录，不会被最后一次评价覆盖。

## 5. 记录购买

1. 进入“购买记录”，选择新建购买。
2. 填写购买日期、渠道等订单级信息。
3. 在同一笔购买中添加一支或多支咖啡豆。
4. 每支豆分别填写规格、数量和实际价格。
5. 保存后，可在豆档案和购买记录中追溯同一订单。

购买记录与饮用记录相互独立：一次购买可有多支豆，而每次饮用始终是一支豆。

## 6. 记录饮用与更正历史

在“饮用记录”中新建单次饮用，可填写冲煮方式、日期、备注，以及本次美式或奶咖评价。历史购买、饮用和评价均可从记录页面更正。

删除流程采用两步保护：先进入回收站，再恢复或永久清除。如果一条饮用是某项综合评价的唯一依据，系统会阻止永久清除并解释冲突，避免评价失去来源。

## 7. 陈列馆、档案与比较

陈列馆支持按状态、品牌、产地、烘焙度、处理法、风味、价格和评价完整度筛选，并采用稳定排序。

- “查看档案”：查看商品来源、购买、饮用和评价之间的关系。
- “加入比较”：最多同时比较三支豆。
- “创建购买”：从卡片或比较结果直接预选咖啡豆进入购买表单。
- “关注”：把采集候选或已有豆加入关注。

豆档案的归档或删除入口会先展示影响。有关联历史或非最小档案只能归档；只有无引用的最小草稿才允许二次确认后永久删除。

## 8. 本地个性化推荐

点击“打开本地推荐”后，可维护冲煮方式、风味、烘焙度、酸度和价格偏好。推荐分为：

- “值得尝试”：尚未饮用的正式豆。
- “适合复购”：已有饮用记录且未被“不会回购”排除的豆。

每条推荐展示主要依据、置信度和数据缺口。规则完全在本机运行；数据或偏好变化后，旧快照会标记为需刷新。普通浏览和记录不会在推荐面板关闭时自动生成快照。

## 9. 联网搜索与链接解析

联网采集只在你主动操作时发生：

1. 输入商品关键词或 `http/https` 商品链接。
2. 查看候选字段及来源。
3. 逐项选择采用、保留现有值或手工修改。
4. 确认后创建新档案，或合并到检测到的重复档案。

解析失败时可以保留来源链接并转为手工录入。豆迹不会绕过登录、验证码、付费墙或访问控制，也不会把个人评价和购买记录发送给目标网站。

## 10. 导出评价结果

导出范围可选择当前筛选结果，或比较台中指定的咖啡豆。选择 Markdown 或 PDF 后创建不可变快照：同一个快照的两种格式具有相同的咖啡豆集合、生成时间和快照标识。

- Markdown 适合放回 Obsidian。
- PDF 适合阅读、打印或分享。

导出文件默认保存在 `data/exports/`。它们是派生结果，不会反向覆盖应用数据。

## 11. 备份、恢复与更新

### 11.1 日常备份

定期复制整个 `data/` 目录到另一块磁盘。应用内部备份不能替代异地副本。

### 11.2 更新应用

1. 退出豆迹。
2. 复制 `data/` 目录。
3. 更新源码。
4. 在 `app` 目录执行 `npm ci`、`npm run setup`、`npm run doctor`。
5. 执行 `npm run build` 后启动。

### 11.3 恢复模式

主文件缺失或损坏、但存在备份资产时，应用会进入恢复模式，不会静默创建空库。选择页面列出的已校验备份恢复。恢复仍失败时，先完整复制 `data/`，再进行排查。

## 12. 常见问题

### 页面打不开

- 确认启动终端仍在运行。
- 检查是否打开了 `http://127.0.0.1:4173`。
- 执行 `npm run doctor`。
- 端口占用时设置 `COFFEE_DASHBOARD_PORT` 后重新启动。

### PDF 导出失败

执行：

```powershell
npm ci
npm run setup
npm run doctor
```

确认 Chromium 检查通过，然后重试导出。成功保存但页面刷新失败时，按页面提示刷新状态；不要连续重复创建新快照。

### 保存时提示版本冲突

另一个页面或刚完成的操作已更新数据。按提示刷新后重新检查输入并提交。不要同时打开两个服务进程共享数据目录。

### 商品网页无法解析

目标站点可能限制访问，或 URL 被本地安全策略判定为回环、私网、危险端口。改用公开商品链接，或保留来源后手工填写；不要关闭安全校验。

### 如何完全卸载

源码版停止服务后删除源码目录即可。一键版先从通知区域退出豆迹，再删除下载的 EXE；它解压的本地运行时和个人记录位于 `%LOCALAPPDATA%\CoffeeDashboard`。如需保留记录，先备份其中的 `data/`；如需彻底卸载，再明确删除整个目录，该操作不可恢复。

## 13. 发布前自检

维护者可运行：

```powershell
npm run verify
npm run test:e2e
npm run test:pdf
```

公开仓库不会包含私人 Excel，因此真实工作簿 dry-run 会自动跳过；其余固定夹具、集成、浏览器和 PDF 测试应通过。
