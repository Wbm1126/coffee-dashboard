## 1. 本期交付

豆迹已形成可在本机独立运行的单用户咖啡豆档案工具，核心闭环如下：

1. 从两份历史 Excel 生成只读预览，显式处理冲突后一次性迁移。
2. 连续补录历史饮用记录，并分别保存美式、奶咖评价。
3. 独立记录多豆购买订单与单豆饮用，支持更正、回收站、恢复及受约束的永久删除。
4. 在陈列馆中筛选、排序、查看来源链、比较最多三支咖啡豆，并直接关注或创建购买。
5. 根据本地事实和显式偏好生成可解释、可复现、不依赖联网更新的个性化推荐。
6. 通过关键词或商品 URL 搜索候选，确认字段后再创建或合并；网络失败时保留上下文并允许手工录入。
7. 按当前筛选范围或比较台指定咖啡豆导出同一快照的 Markdown 与 PDF。
8. 在豆详情中先查看关联影响，再归档有关联历史的豆；只有无引用最小草稿可二次确认后永久删除。
9. 数据仅保存在本地 JSON，使用 revision 并发控制、原子替换、校验备份、恢复模式和只读兼容模式。

产品边界保持不变：不包含在线账号、多用户协作、云端同步、移动端和自动下单。价格监控属于后续能力；本期推荐为本地个性化推荐，不要求实时联网更新。

## 4. 最终审查已关闭的问题

- 导出重试改为使用持久化的不可变报告事实；旧快照无法可信重建时明确拒绝。
- 503 的 recovery/read_only 响应可以进入对应客户端界面。
- 恢复与普通写入共享串行队列，恢复后 revision 单调增长；缺主文件但存在备份时进入恢复模式。
- 采集响应截断、错误和中止均安全失败，不再等待超时或留下未处理事件。
- 补评价队列丢弃旧 revision 的迟到响应。
- 采集确认使用稳定 operation key，未知成功后的重试不会重复创建豆档案。
- 自动备份仅保留最新 100 组已验证的应用备份；未知、孤立、手工或校验失败文件不自动删除。
- 豆档案生命周期和指定豆导出补齐页面入口。

## 5. 已知边界与后续前置条件

- 受控实时采集 smoke 在本机被 DNS 环境映射到非公网地址，安全策略按设计拒绝。固定 HTML/JSON-LD 夹具和 URL 安全测试已通过；需求约定实时站点失败不覆盖夹具结论。
- 当前是首个 `schemaVersion: 1`，没有历史 schema 可迁移。首次提升 schema 版本前，必须补升级前备份及真实迁移回归测试。
- repository 的写队列是单进程内保护；不要让两个服务进程共享同一数据目录。
- 离线 E2E 阻断浏览器外部请求；服务端采集出口由 URL 策略、DNS/IP 重校验、大小限制、总截止时间及夹具测试约束。
